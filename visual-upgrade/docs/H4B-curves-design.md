# H4B 后续弯坡道路接入设计

状态：0.6.2已按此设计接入弯坡高速预览；验收范围及剩余缺口见 [H4B-curves-review.md](H4B-curves-review.md)。以下保留设计依据。

## 当前必须一起修改的假设

`Road.locate()`在高速上直接返回世界y/x；HighwayDriver以世界y比较前后、以世界x比较车道，并按世界y推进变道。复位、生成、路段回收、HUD里程也使用这些值。只把渲染路面掰弯，会令交通车驶离道路、净距错误、复位到路外。因此不能先画弯路再局部补判断。

## 第一版几何选择

采用每1000米道路弧长一个缓弯/坡道单元，内部仍按200米分段加载。单元局部横移使用首尾一、二阶导数均为零的六次隆起函数 `b(t)=64t³(1-t)³`；横向幅度60米，高度幅度先不超过12米。随机源只选择左右弯与上坡/下坡的符号，避免不同加载次序影响道路。

局部曲线先令 `x(s)=±60 b(s/1000)`、`z(s)=z0±H b(s/1000)`，再积分 `y'(s)=sqrt(1-x'(s)²-z'(s)²)`。左右和上下符号不改变每个单元的y前进量，所以全局单元位置可以直接由编号计算，不需要从第0段累计构建到当前段。这给出真实弧长、固定内存和稳定回访，同时允许随机左右弯与山坡组合。首版几何变化范围有限，之后再扩充曲线模板，而非宣称任意随机道路已实现。

采用固定精度表保存一个单元的局部积分值与导数，数值误差先通过长度和投影测试。负编号使用floor，200米交界由同一个采样函数计算同一组边界顶点，不能各段各自估计法向。

初步数值计算：60米横移/12米起伏、1000米弧长对应约989.959米y前进量；最大坡度约4.125%，最大平面曲率0.00144/m。以2.5 m/s²横向加速度约束，最急处对应约150 km/h。建议首版网格间隔5米。记录在 `logs/h4b/curve-design/geometry.json`；这是设计计算，不是游戏中物理验收。

坡道先独立验证。基面抬高到能容纳最低谷且始终高于海平面的位置；车体出生高度、地形、树根及护栏同时读取道路高度。不要把地形仍放在旧的平面z上。

## 接口和控制分工

1. 道路查询统一为 `sample(s, lateral)` 和 `project(position)`；采样返回位置、朝向、坡度、曲率。投影返回真实道路弧长s和有符号横向偏移d。碰撞与显示共用采样及网格。
2. 交通感知、IDM前后净距、目标车道预约、变道进度统一在s/d坐标计算。物理世界速度投影到道路切向/横向；不能继续用单一世界y速度。
3. 转向控制仍读取真实车体位置/朝向。目标点取前方s加预瞄距离、给定横向目标d；保留当前连续方向盘和物理轮胎。弯道限速先复用滨海控制器按曲率计算的舒适横向加速度约束。
4. 复位通过道路查询生成候选位姿，继续检查车体占用与后车接近；不会因道路弯曲放弃安全复位规则。
5. 分段编号由道路弧长决定，重定位仍是整个世界的纯平移。全局s不因世界原点平移而改变。相机、插值快照及场景根节点只跟随同一平移量。
6. 装饰的随机位置先生成局部s/d再映射到道路外侧，按真实净空布置。弯道网格步长以曲率和1.5厘米支撑误差目标确定，不沿用直路40米长面片。

## 实施顺序和职责

- 高能力模型：几何采样/投影及误差验证；修改Road边界和HighwayDriver的坐标分工；复核重定位、变道/跟车、道路支撑与相机连续性。
- Luna：接口确定后生成同源路面/标线/护栏网格，映射树木与地形；编写明确测试夹具、记录和包运行说明。不得单独改动力学和把车辆按路径设位置。
- 先只启用弯道、验证后再启用坡道。保留直路作为回归场景。每次启用都先跑真实物理场景，再打开试玩入口。

## 接入门槛

十个种子、正负编号、不同加载次序；sample/project往返；所有接缝轮迹/中心/路肩支撑误差≤1.5厘米；玩家最高速度与NPC跟车/变道；弯顶/坡顶制动；R复位、倒退、跨原点与停在接缝；再做100公里和可见窗口耐久复测。只有直路通过不能替代这一轮验证。
