# 车辆物理完善路线

2026-09-30。参考用户提供的《CoastalDrive 物理系统对话整理与规划》（2026-09-28），以当前主版本 `6fbcd36f24c92e267428c1076f6e8fbd2a4af1db` 的源码和实际试验为起点。文档中的讨论是设计参考；本轮用户要求按功能分区、代码直接，并明确采用每项机制的旧车 A / 新车 B 标准试验对照。

## 实施原则

围绕可解释的物理机制组织任务。同一个机制可以协同调整多个参数和代码环节，不要求一次只改一个参数。先保存 A 的配置、初始条件、控制时序、120 Hz 轨迹和指标，再在相同试验中运行 B。比较变化方向与幅度是否符合汽车理论，同时运行相关回归；重点是检验汽车理论与游戏行为的因果关系。若理论方向与结果不符，先解释或修复模型，不改阈值掩盖问题。读数新增和职责重构要求物理状态保持一致。

同一权威物理核心供玩家、交通和未来研究控制使用。驾驶辅助改变控制请求，车型电子系统通过执行器工作。Bullet 保留刚体、重力、碰撞、道路接触、射线悬架和积分。自定义轮胎力接管与 Bullet 摩擦旁路作为一次完整迁移验证，不能把两套轮胎力叠加运行。

代码按职责组织：接触与诊断、驾驶辅助、动力总成、转向、轮胎、电子控制。随实际功能拆分文件，不预建管理器、注册器或通用框架。标准试验与分析工具放在 `tools/physics/`，证据放在 `docs/evidence/<任务>/`。自动物理验证与用户驾驶体验分别记录。

## 功能任务与顺序

| 功能 | 任务 | 完成条件 |
|---|---|---|
| 道路载荷 | PHYS-01 道路坡度与车身俯仰分离 | 平路抬头不生成坡度阻力，坡面正反向符号正确，空中不伪造支撑；A/B 加速与制动对照 |
| 接触诊断 | PHYS-02 四轮轮荷、悬架、接触与 skid | 只读快照与 CSV，真实单位、明确采样时刻，reset/重定位正确；新增诊断不改变轨迹 |
| 标准试验 | PHYS-03 定圆、阶跃、弯中制动、split-μ | 固定初始条件与输入，保留完整轨迹；报告模型现有能力与缺口 |
| 碰撞与支撑 | PHYS-COLL-01 高速斜撞护栏越顶诊断 | 旧基线与新版本均复现120km/h越过0.8m护栏；区分越顶、穿透、轮射线支撑与刚体冲量，保持原测试阈值 |
| 控制职责 | ARCH-01 辅助与动力总成拆分 | 默认玩家行为保持；研究入口绕过键盘辅助，实际执行器仍有物理限制 |
| 转向几何 | PHYS-04 Ackermann | 内轮大于外轮、正反方向对称；低速定圆 A/B 与交通驾驶回归 |
| 轮胎核心 | PHYS-05/06 四轮角速度与滑移诊断 | 车轮转动方程、低速/倒车符号、κ/α 数据可检验；不把视觉轮转当真实轮速 |
| 轮胎受力 | PHYS-07/08/09 自定义力及摩擦所有权 | 接地点施加唯一 Fx/Fy，联合滑移平滑饱和；能量、方向、时间步稳定性和碰撞回归 |
| 极限行为 | PHYS-10 空转/抱死 | 有驱动转矩与制动转矩因果关系；无辅助状态在标准试验中出现可验证的空转/抱死 |
| 电子控制 | CTRL-01/02/03 ABS/TCS/ESC | 单轮控制由真实滑移/横摆反馈产生；开关 A/B 证明机制有效，所属车型与输入辅助分开 |
| 车型参数 | VEH-PHYS 几何、惯量、动力、轮胎、驱动布局 | 同一实现传配置，物理轮心与外观自洽；参数改变自然产生性能变化 |
| 研究控制 | AI-PHYS 无窗口观测与直接控制 | 同一固定步与物理核心，明确 reset、观测、控制与终止，不引入训练库作为前提 |

PHYS-01～03 先构成测量基础。全量复核发现的旧基线护栏越顶问题单独进入PHYS-COLL-01，不因为旧版也失败就视为通过。后续任务在前置证据通过后展开；核心迁移由主代理负责，明确的记录、测试与实现可交给用户允许的 GPT-6.1-Sol low / Luna。

## 当前验收口径

当前轮胎横向力仍由 Bullet 射线车辆计算，项目纵向力另有准静态 μFz 限幅。诊断 skid 不是物理滑转率；四轮悬架力与准静态前后轴荷估计分别保存。标准工况的响应曲线用于 A/B 机制分析，不冒充真实车辆实测标定。

每个任务包保存基线、改动范围、A/B 结果、理论结论、T0/T1 证据与下一入口。小阶段收口运行 T2；完整物理阶段的 T3、可见窗口性能与用户驾驶结论完成后，再判定整个阶段通过。
