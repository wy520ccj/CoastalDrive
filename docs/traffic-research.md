# 交通行为研发依据与实现边界

后续更新：0.6.1的驾驶风格、后方逼近让行和侧向预测见 [traffic-v2-review.md](traffic-v2-review.md)。以下0.6.0说明保留作设计沿革。

2026-09-21。用户新增要求：交通车辆应体现异速、变速、变道与现实交通互动；保留旧项目意图，避免原有随机脚本的状态与冲突问题。

## 参考案例

1. [IDM 作者说明](https://traffic-simulation.de/info/info_IDM.html)：纵向行为由自身速度、前车净距、相对速度决定，期望速度/车头时距/舒适减速度描述驾驶风格。本文采用它作为目标加速度，交给本游戏的油门/刹车执行，绝不直接积分覆盖 Bullet 车体位置。
2. [MOBIL 作者说明](https://traffic-simulation.de/info/info_MOBIL.html)：将变道收益与目标车道后车安全分别判断，考虑其他司机受影响的程度。借鉴其安全与收益思路；本版采用保守简化收益，不宣称完整复现 MOBIL（尚未计算原车道后车收益项）。
3. [Farama highway-env](https://highway-env.farama.org/dynamics/vehicle/behavior/)：可检查、可复现的 Python 交通行为实现，IDM 与 MOBIL 分别处理纵向与横向决策，适合参考控制/行为分层及未来学习环境。但其车辆模型不能直接替代当前四轮动力学。
4. [SUMO 连续横向运动](https://sumo.dlr.de/docs/Simulation/SublaneModel.html)：变道有持续过程，不能瞬间跳到另一条车道。本项目通过连续平滑目标路径与实际方向盘执行，车体运动仍由轮胎与碰撞求解。

参考的是模型与结构；本轮没有复制第三方源码、引入 SUMO 服务或增加 highway-env 依赖。

## 旧代码取舍

详见 [旧交通代码审查](legacy-traffic-review.md)。保留独立决策时钟、冷却、意图状态、执行前安全复核与冲突仲裁。重写随机源、未完整初始化的状态、中心点间距、固定切入刹车脚本和单向回收逻辑。静态风险不等于已经复现了旧程序每一个 bug。

## 当前 0.6.0 预览实现

- 无限直高速采用每车独立、可复现随机源。期望速度初值21–33 m/s、时距1.5–2.1 s，司机之间保持差异；数值是游戏初始标定，不是现实驾驶人群统计数据。
- 每15–35秒重新抽取小幅期望速度偏移，并限制目标变化率。油门与制动仍经过已有响应模型；前车、停车空间和变道安全优先于随机偏好。
- 高速纵向采用 IDM 目标加速度与踏板反馈。舒适减速及紧急刹车不等于在任意玩家恶意切入下都能避免碰撞。
- 行为状态保持少量明确状态：巡航、打灯等待、变道、事故停车/恢复。提前1秒打灯，连续路径约4秒/至少45 m完成；提前完成以实际横向偏差和朝向判定，不按计时强制写车道坐标。
- 目标车道前后净距、相对速度、后车所需减速度、5秒预测间隙同时判断。现有/本周期变道意图统一预留，避免两辆车争同一个空隙。
- 打灯阶段若间隙消失则放弃；刚开始横移且仍在原车道内时也可放弃。已经跨线后同时参考两车道前车制动，避免来回摇摆。
- 完成后8–15秒冷却，避免频繁左右横跳。只有明显收益才换道，不靠随机强行切入制造难度。
- 回收车在远处以安全净距重新加入；不将事故中的可见车传送回正。交通转向灯与快照同步闪烁。
- 滨海和旧有限预览保留 H4A 已验证控制器；当前新变道策略只支持无限直高速，弯道、坡道必须专项扩展。

## 接下来需要的研发

1. 真实驾驶窗口30分钟连续观察，并记录内存/帧时间，检查近处生成、远处跳变和连续变道画面；离屏里程测试不能冒充这一项。
2. 单独加入“回右侧车道”、明确超车完成判断、三档交通密度；密度按可用距离和流量标定，不能只是挤进更多车。
3. 更复杂受撞恢复、变道中玩家横向插入、堵塞消散测试；对制动距离不足的冲突记录发生过程，不能删车掩盖。
4. 无限道路弯道与坡道需统一弧长、横向投影、道路曲率和重定位；先验证直路，不能直接把 world-y 算法套在曲线。
5. 正常车流与训练用风险事件分开。未来训练场景可指定慢车/急刹/切入事件，但普通驾驶默认不注入故意撞玩家的脚本。

## 验收方法

固定种子覆盖慢车、静止车、后车高速接近、双车争道、变道前间隙消失、受撞、回收。保存失败的种子/tick/车辆对。统计速度分布、变道数、碰撞、道路偏差、长期停死与段/物体数，不以“程序没崩”作为通过。
