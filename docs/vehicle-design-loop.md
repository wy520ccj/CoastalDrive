# 车辆设计 → 实验 → 游戏

从游戏主菜单进入实验室会带入当前车辆，保留完整工程配置及ABS/TCS/ESC开关。实验室仍允许慢于实时运行；游戏继续沿用已有120Hz单机械步与键盘辅助。

## 操作

1. 游戏主菜单选车，再进入实验室；也可直接启动 `launchers/vehicle-lab-double.cmd`。
2. 在高级参数修改质心高度、轮胎基准载荷，或通过“记录 → 导入工程模型”载入完整工程车。开始并完成一次试验。
3. 点顶部“游戏联动”，核对试验车辆；“运行游戏对照”将按参考试验的逐拍直接命令运行游戏积分配置，生成原始记录与差异报告。“打开报告”查看结果。
4. 点“保存车辆并试驾”，保存参考试验及完整有效配置，自动进入滨海自由驾驶。返回游戏菜单再进实验室，继续研究同一辆车。

应用始终取打开联动面板时的已完成试验。之后修改但没有重新试验的输入框不会参与。路面μ、电子开关与工程硬件一起沿用，完整数值见保存的vehicle.json。暂停、失败、碰撞和复位终止记录不能作为本入口的已完成试验。

工作区车辆保存于 `%LOCALAPPDATA%/CoastalDrive/design-loop/vehicle.json`；下次启动普通游戏或实验室会恢复。显式 `--vehicle-design` 优先于已保存车辆。车库保持同设计ID时只换外观/车漆，保留工程车；明确选其他车型时改用新车型默认硬件并保存。游戏电子开关修改也保存到该车辆。

原始试验和游戏对照默认保存于 `%LOCALAPPDATA%/CoastalDrive/experiments/` 的独立时间戳目录。原始记录不覆盖。应用车辆的报告路径随工作区文件保存；阶段性能与手感仍由实际驾驶验证。

## 对照读法

两次计算使用同一120Hz外层固定步、工程硬件、工况、初始化流程与逐拍VehicleCommand。游戏配置沿用生产 `DrivingMode.GAME.configured_vehicle`，只将机械子步设为1。参考记录的源版本、原生库与当前不同时，先重做参考试验。原记录未保存积分配置字段时按既有参考记录处理；新增游戏记录明确标记game，并按该配置复算。

定圆/双移线对照重放参考驾驶员的命令，不在游戏侧重新运行路径驾驶员，便于观察积分差异。每侧各自真实停车、碰撞或达到时长时结束；参考命令先耗尽而游戏尚未停车时明确记录 `reference_commands_exhausted`，停车距离留空。公共时间段的RMSE/最大偏差和各自终止时刻指标分开报告。

`comparison.json`保留完整数值和配置差异；`reference/`与`game/`各自保存命令、快照、CSV、源码/运行库摘要、工程指标和HTML报告。当前同次对照使用同一运行库精度，报告标明32/64位；不将双精度同库对照解释为跨运行库标定。

本轮提供误差观察和试驾闭环，尚未制定车型误差合格范围或自动调参，也没有建立AI训练运行档。后续先确定可接受误差和工况覆盖，再做游戏参数标定及最小无窗口AI接口。原实车标定、完整能量/精度、长期性能与人工体验Gate继续单独记录。

## 功能分区

- `vehicle_workspace.py`：同一工程车的交接与保存。
- `lab_game_comparison.py`：积分对照、误差与结果导出。
- `ui/lab_design_loop.py`：已试验车辆的对照/试驾操作。
- `main.py`：关闭原窗口/会话后再建立下一工作方式。
