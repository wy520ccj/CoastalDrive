# PHYS-DRIVE-01 接入设计准备

2026-10-03。当前PHYS-ROT-01完整T1-r1仍在验证，这份设计及所有台架仅写证据目录，273生产/测试/工具Python文件继续冻结。实际接入待ROT的T1收口；本文件不代表动力总成已经完成。任务目标仍是完整双模式、通用参考车后实车型、同标准A/B，详见[全目标](../../physics-goal-audit.md)。

## 当前接口缺口

`powertrain.py::advance`以轮速和起步目标平滑生成RPM，输出预先确定的轮端转矩；没有发动机独立惯量和离合负载反馈。发动机制动又成为后轮干式制动容量，不能表现真实回拖功流。现在已有轮轴/车身共同末状态与机械轴，下一块将真实曲轴、离合、齿轮、开放差速器一并接入同一子步，转矩不在解轮胎之前定死，不重设运行RPM/轮速。

后驱通用参考车先闭合；FWD/AWD和限滑差速器随后按实际需要扩展。首块保留曲线、轮胎、三电子增益、碰撞/悬架和120Hz。困难仿真的惯量/离合参数为明确设计值，不从原游戏加速门槛倒推发动机曲线。游戏便利控制和参考车机械参数分开。

## 同末状态与功账

发动机绝对轴速ωe、正转机械轴ae、惯量Je；轮正滚动标量ωi的物理自旋为`−Jiωiei`，相对壳体正转为`ui=ωi+Ω·ei`。曲轴相对速度为`ue=ωe−Ω·ae`。带符号总齿比R，开放差速器输入速度`x=R(uL+uR)/2`，离合滑差`δ=ue−x`。

燃烧/曲轴净转矩Te与离合转矩Tc满足`JeΔωe/h=Te−Tc`，壳体轴向反力`(Tc−Te)ae`。等分输出转矩`D/2`作用于两轮；D是机械约束算出的输出总转矩。共同总自旋为`S=Jeωe ae−ΣJiωiei`，陀螺反力取`S_end×Ω_end`。外部接触力矩以实际p×F记账。

有限离合容量C：`−C≤Tc≤C`，容量内末δ=0，容量外转矩与末滑差同号；热耗散为`h Tc δend`。零容量分离时，发动机仍受燃烧/摩擦及轴向输运，不锁到轮速。

齿轮损失不能在回拖时仍简单乘η。选定输入端损失转矩L、`D=R(Tc−L)`，热耗散`h L xend`。移动时功方向决定同一效率η：

| 功方向 | 输出总转矩 | 原始损失功 |
|---|---|---|
| Tc x > 0，发动机向轮端传功 | D=η R Tc | h(1−η)Tc x ≥0 |
| Tc x < 0，轮端回拖发动机 | D=R Tc/η | h(1−1/η)Tc x ≥0 |

这可写成输入端阻抗的静摩擦区间：Tc≥0时`L−=−(1/η−1)Tc`、`L+=(1−η)Tc`；Tc<0时交换相应方向，`L−=(1−η)Tc`、`L+=−(1/η−1)Tc`。x>0取L+，x<0取L−，静止时在区间内解x=0。η=1恢复理想齿轮。每个Tc试算内先解L的同末速度约束，再解离合δ；现有Brent只求同一有界物理残差，不作失败fallback。生产接入前仍须用完整轨迹验证低速活动集及效率模型的适用范围。

总能量保留发动机/四轮/车身动能、胎体储能、材料/路面耗散、制动功、离合功、齿轮热与后向积分损失：

`Δ(Kbody+Kengine+Kwheels+Ucontact)+E_BE+Econtact+hΣBiui+hTcδ+hLx = hTe ue+Wsteering`。

S×Ω功为零，转向指定轴运动功继续按ROT单列。这里的全部等式是冻结瞬时世界轴向模型；真实有限旋转仍须原生120/240/480/960Hz诊断，不能从单步证明替代世界积分。

## 接口求解成本准备

上述嵌套根每次都重算四轮，接入前还需控制其成本。固定当前轮胎力与陀螺项时，可以直接解有限离合和齿轮两个约束，随后重新计算原全局接触/角动量残差；这不是把两个系统分开推进。

取广义速度`q=(Ω,ωe,ωL,ωR)`，质量为车身完整世界惯量、Je和Jw。离合滑差的梯度为`gc=(−ae−R(eL+eR)/2,1,−R/2,−R/2)`；齿轮输入速度梯度为`gl=(R(eL+eR)/2,0,R/2,R/2)`。两反力分别是`−Tc gc`和`−L gl`，燃烧力为`Te ge`，`ge=(−ae,1,0,0)`。发动机粘性摩擦c作用于真正相对速度ue，以`M+h c ge geᵀ`隐式积分；利用一次秩一逆求得有效机械响应，摩擦热始终为`h c ue_end²`。

记有效逆矩阵A、`Dcc=gcᵀA gc`、`Dcl=gcᵀA gl`、`Dll=glᵀA gl`，则共同末状态满足：

`δend=δfree−h(Dcc Tc+Dcl L)`，`xend=xfree−h(Dcl Tc+Dll L)`。

移动齿轮的损失L为对应符号端点，锁止离合解δ=0；滑动离合取±C；静止齿轮解x=0。枚举实际锁止/滑动、静止/运动组合，一次1×1或2×2解获得候选，再按同一容量/符号/1e−11rad/s条件选可行解。边界模式标签可以重复，但机械反力必须相同；没有可行解显式失败，不回退到另一种物理机制。

- [360组固定阻抗随机台架](drive-port-active-initial/summary.json)，含正反挡、η=.88/1、零/有限离合和三档隐式曲轴摩擦。直接活动集与独立双层二分最大转矩差6.04e−12Nm，最大能量误差7.11e−12J。
- [72组定向活动集台架](drive-port-modes-initial/summary.json)，完整世界非对角惯量、不同后轮机械轴，九种离合/齿轮组合×两齿比×两h×两η全部覆盖；最大能量误差4.91e−13J。各自由端由指定可行机械状态反推初态，没有重设运行末速度。

## 非线性四轮接触的活动集联合原型

曲轴/齿轮的两反力还须与当前单轮干式制动一起确定，才能在局部轮胎牛顿求解中保留真实机械响应。新增制动梯度`gu=(ei,0,当前轮1、其余轮0)`、反力`−Bi gu`，三端口梯度为`(gc,gl,gu)`；对应自由速度是离合滑差、齿轮输入速度及该轮相对壳体转速。令D为三梯度对有效逆质量A的3×3响应，则`send=sfree−h D(Tc,L,Bi)`。离合锁止/滑动、齿轮静止/正反运动、制动锁止/滑动组合按实际容量/符号解1～3个约束；系数在当前子步固定，上一真实活动集可先检查，失去可行性后再检查其他物理状态，没有数值失败fallback。

- [432组三端口台架](drive-brake-active-initial/summary.json)：27类状态×正反齿比×两h×两效率×前/后制动，完整世界非对角惯量与曲轴摩擦。独立嵌套根反力最大差1.18e−11Nm、能量误差2.09e−12J；接触力对三反力的解析导数与独立有限差分最大差9.13e−11。
- [48组非线性四轮共同末状态](drive-contact-joint-r1/summary.json)：每个局部Fx/Fy试算同时解Tc/L/Bi，再更新四轮共享状态及总转子陀螺；复用生产接触目标和解析导数，保持局部0.0001N、全局0.001N、20轮和制动1e−9Nm门槛。最大7轮、末力残差0.000960802N、制动残差0；能量误差1.51e−11J、角动量4.09e−13Nms。与原嵌套根台架最大力差0.000251190N、离合差7.02e−6Nm、曲轴差9.17e−8rad/s，原始差异保留，不声称逐值相同。

## 接入职责

`powertrain.py`持有曲轴真实ω和动力总成请求/执行器状态；RPM由相对壳体ω观测派生。燃油/节气门、怠速、红线、自动离合与自动换挡是明确控制，不在积分后钳曲轴ω。既有torque_response可作为节气门执行器的时间参数，具体设计值先台架稳定性验证，不能默认为轮端再加一层滤波。

`Vehicle.apply_command`继续形成同一真实执行器请求，电子削矩作用于燃烧请求，分轮制动仍经过Brakes。`Tires.advance`负责同一子步调用联合机械求解与一次冲量提交；轮/发动机的独立状态从同一求解结果更新。直接使用有限离合/齿轮约束函数，不建立Manager或通用求解框架。

`VehicleCommand`增加可选显式gear/clutch请求，None清楚表示采用自动策略；研究入口可绕过人类驾驶辅助但仍驱动同一物理执行器。Snapshot包含真实engineω/相对RPM、挡位/换挡阶段、离合容量/反力/滑差/耗散及齿轮损失，UI只显示这一快照。

显式研究请求下，挡位决定机械连接，节气门决定曲轴转矩，制动与离合分别作用实际部件；不能沿用旧`braking→drive_torque=0`把同时踏油门/制动的研究输入隐式改写。人类倒车/踏板互斥便利仍在DriverAssist内形成请求。倒挡只改变齿比符号，燃烧轴向不因车辆方向翻转；分离离合或空挡时仍允许真实曲轴自由响应。曲轴有效转矩曲线与闭节气门损失的功口径须明确，不能把净制动功率曲线的既有摩擦重复扣除。

自动换挡采用有限速率离合行程：卸载至实际容量0→切换无载齿比→按实际同步滑差重新结合，曲轴/车轮连续。起步离合控制以实际曲轴速度与负载调节容量，不能把旧launch_rpm公式当作真实发动机状态。零怠速偏差、红线控制、倒挡/空挡和离合分离均用因果台架验证。

## 下一块验收

生产冻结A为ROT收口版本、完整reference-v9及明确初始发动机/轮速。B同输入检验起步/全油门、松油回拖、换挡/中断换挡、空挡自由转动、坡停、倒车、split-μ与TCS介入、离地轮/再接触、制动。保存全过程和所有能量端口，观察理论方向；两模式各自比较，不据困难仿真旧加速指标调曲线。
