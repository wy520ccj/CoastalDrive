# 下一块：驱动布局与开放式分配

状态：规划，未实施。当前DRIVE-01完整T1/T2尚未收口，先保持其280Python文件冻结；收口及本地提交后再建立下一任务。用户整体目标中的FWD/RWD/AWD、限滑与轴惯量不能由当前后驱开放差速代替。

## 功能边界

先实现同一有限机械核心中的前驱、后驱和具有理想开放中差的四驱；发动机曲线、曲轴惯量、有限离合、齿比、双向效率、四轮制动与接触方程保持。内部轴/齿轮惯量及有限限滑转矩随后单独做物理机制，不给未建模轴补假转速。两个模式仍共用核心，默认认可的游戏RWD参数保持；其他布局由明确通用设计参考配置验证，再用于实车型。

MathWorks [Differential](https://www.mathworks.com/help/sdl/ref/differential.html)明确将侧轴差速自由度与平均驱动运动分开，用三端功守恒约束传动；[Transfer Case](https://www.mathworks.com/help/autoblks/ref/transfercase.html)也把前后轴分配、输入轴、损失与储能分别记账。以下是适用于本项目现有八维速度的理想刚性、忽略中间轴惯量的推导，并非复制其动态轴模型。

## 同一配置产生机械与电子行为

以设计前轴份额β∈[0,1]作为一个直接配置量，β=0为RWD、β=1为FWD，0<β<1为理想开放中差AWD。四轮功共轭权重w=(β/2,β/2,(1−β)/2,(1−β)/2)。AWD的β为固定差速几何等效份额，不是随抓地切换的主动分配策略。

设a_i为当前真实机械轮轴方向，s_i=ω_i_abs+Ω·a_i为轮相对壳体轴速。差速输入s_d=Σw_i s_i，齿轮侧速度s_g=R s_d，离合滑差s_c=ω_e_abs−Ω·a_e−s_g。轮端转矩T_i=w_i R(C−L)。从这些速度梯度形成壳体/曲轴/四轮共同约束，继续同末状态求解；转向前轮使用本拍实际机械轴，不能读上拍接地轴当本拍传动轴。

Tires的驱动轮轴速、共同求解梯度和逐轮实际转矩、TCS驱动轮集合、研究参数读回都从同一配置产生。TCS只调实际被驱动轮；手动gear仍按真实已挂挡位取方向，空挡不产生驱动资格。ABS所有轮保留，ESC轮制动仍由原横摆预算形成。新增布局不会增加第二套车辆状态或UI物理。

源码按已有功能块改vehicle_config、tire_drivetrain、vehicle_tires、vehicle_traction和必要Vehicle接线；纯配置与已有直接函数足够，不建动力总成Manager、布局注册器或策略继承层。配置边界处理错误，内部接口直接访问。共同求解的原力残差、容量、能量与反力门槛保持。

## 验收前置与完整性

1. 解析机械台架先核对三布局的驱动集合、每轴左右等矩、反向功流、壳体反力、离合滑差和虚功。斜轮轴/前轮转向/不同轮速共用同一方程；移除前轴反力的负对照须被原能量/动量门槛检出。
2. 默认RWD相同配置/输入与DRIVE-01冻结版本比较共同旧字段，保持认可路径。机械关闭兼容分支记录自己的配置与覆盖范围，不把有限核心的关掉结果冒充FWD/AWD真实机械验收。
3. 同车仅改变β做标准起步、加速、定圆、阶跃、弯中制动、低附着/单轮离地/再接触及倒车A/B。理想开放差速必须允许差速，一轮失附着时不能人为把它的ω钳到高附着轮；有限转子惯量的瞬态也不能用静态最小抓地矩截断。逐tick功/热/转矩与真实轨迹分别核对，不要求所有布局所有指标改善。
4. 电子控制开/关配对：前驱TCS只在前轮请求、后驱只在后轮、四驱在所有驱动轮；关闭路径和真实gear覆盖方向、空挡、换挡卸载仍有原生完整断言。
5. 补全参数表、配置IO、reset/rebase/NPC回收/模式重建/研究命令观测。T0选相关短测；完整T1及功能组T2按任务包执行，T3/实际前台性能/用户两模式驾驶仍分别验收。
