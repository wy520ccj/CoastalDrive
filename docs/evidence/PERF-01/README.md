基线 `02e6217`，环境为 RTX 4060 Laptop GPU / i9-13900HX。诊断期间没有修改游戏源码。短测固定 1920×1080、种子 23、同一路线；离屏测量只用于相对比较，不等同于可见窗口性能 Gate。显卡/驱动缓存未清理，案例基线存在顺序漂移。

## 运行期主要成本排序

离屏 A/B（`runtime-offscreen/summary.json`）中，基线前后为 56.98 / 56.73 FPS：

| 单因素关闭 | FPS | 对比约提升 | 证据判断 |
|---|---:|---:|---|
| 交通更新/仿真链（零交通） | 69.66 | +12.7 | 强信号；同时移除交通更新、快照和画面，不是纯物理成本测量 |
| 阴影 | 66.98 | +10.0 | 强信号；单因素开关，短测筛查 |
| 整组 coastal visuals | 65.37 | +8.4 | 强信号；定位到环境组合，尚未定位具体资产/绘制成本 |
| 旧主车 | 57.92 | +1.2 | 弱信号；在基线波动范围附近 |
| 无反射 | 55.82 | 无提升 | 没有发现收益 |
| 无水面 shader | 55.80 | 无提升 | 没有发现收益 |

这些开关互不独立，收益不可相加。`traffic-split/summary.json` 保留 8 车模拟、仅隐藏车体/车轮/信号画面后为 58.35 FPS，夹测基线 57.17 / 56.82 FPS；这支持交通主要成本处于更新/仿真链而非车辆网格绘制。它没有单独测量每个交通子系统。`art-split/summary.json` 中单独关闭 slice / props / terrain 为 60.61 / 61.71 / 57.13 FPS，但夹测基线从 58.83 漂至 56.05 FPS；因此这些只构成候选排序，不能确定各自精确成本。

主车源资产为 31,760 triangles、29 Geom、11 种材质；旧模型为 2,088 triangles、8 Geom。可见窗口早期短测换旧主车约 +1 FPS，反射/补光未见稳定收益。模型面数较高是可记录事实，不是本轮确认的主瓶颈。详见 `vehicle-asset-structure.json`。

性能计时扰动 A/B/A（`measurement-ab/summary.json`）为 57.84 / 58.37（关闭 update CPU 钩子）/ 59.89 FPS，差异小于基线漂移，未见计时器造成 PERF-00 级别退化。早期可见短测 `runtime-screen/` 未包含窗口状态，只作辅助。

## 无效样本和门槛

- `focus-probe/01-baseline/run-01/report.json` 的窗口前景比例约 0.154，窗口在约 85% 的采样秒数最小化。该段约 8 FPS 与同阶段约 8 FPS 基线都标记为无效，不纳入性能排序。
- `runtime-screen/09-zero_traffic/` 行驶距离未达到 365 m 验收要求，且接近窗口最小化阶段；无效。
- PERF-00 记录的 47.62 FPS 当时没有窗口焦点/最小化数据。保留为历史值，但不能据此认定代码回退，也不能断言它来自最小化窗口。
- 300 秒离屏长测 `runtime-long-offscreen/01-baseline/run-01/report.json`：55.44 FPS、P95 22.04 ms、P99 24.66 ms、仿真丢时 0。十个 30 秒桶为 56.71、55.08、55.06、58.29、52.98、56.82、56.37、55.94、56.22、50.88 FPS。它没有逐桶持续下跌到 47.62，但离屏数据不能代替可见窗口 Gate。
- 用户要求停止长时间实验后，没有继续 300 秒可见窗口复测，也没有继续 traffic CPU 矩阵。PERF-01 不宣称当前可见窗口通过 60 FPS / P95 25 ms 门槛。

结论强度：启动大头在海岸场景创建（强）；驾驶切换约 1.4 s 来自既有道具重建（强）；运行期阴影、交通链、整组海岸画面有明显 A/B 信号（强到中等，受离屏/短测边界约束）；单个环境子组、具体 draw/CPU/GPU 分摊、47.62 FPS 的有效窗口根因（未知）。本轮只交付诊断，没有性能优化。
