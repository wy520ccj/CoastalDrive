# 左侧路肩的连续遮蔽

2026-09-30，用户指出近处暗、远处亮，明显分界随车辆前进。2048阴影图的95m覆盖范围跟随玩家，连续护栏的投影在范围边缘中断。PCF只能平滑像素边缘，不能补齐远处投影。第一份尝试仅让边缘渐退，用户明确拒绝仍然一暗一亮；最终不再用距离渐退解决护栏一致性。

最终按固定太阳方向，把0.8m连续护栏在当前弯曲/坡面上的遮蔽坐标保存在现有道路顶点数据中，路肩、标线、排水沟和金属排水盖统一接收。它不依赖玩家或阴影图距离；与真实实时投影取较暗值，车辆/门架/树木等原有阴影继续保留，护栏仍向车辆和地形投影。没有关闭全局阴影、扩大阴影图或叠加共面透明面。物理几何、道路法线、材质底色和纹理坐标保持；原有相机/灯光参数不改。

依据[Unity Shadowmask官方说明](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/shadowmaskmode/shadowmask)：静态遮蔽跨越实时阴影距离，动态对象继续用实时投影。本项目固定太阳和规则连续护栏使解析遮蔽足够，不引入整套光照烘焙框架。实时车辆/设施投影仍在有限覆盖边缘渐退，该过渡不再承担护栏路肩的连续性。

## 真实渲染验证

- 弯坡1080p、直道/弯道720p，各24帧每帧前进2m，冻结物理的镜头/光源连续帧检查通过。原始帧和视频在logs/HWY-03/continuous-{hills,curves,straight}，不是驾驶FPS证据。
- 固定1080p镜头，太阳覆盖中心前移60m（16帧×4m），沿左路肩62–95m采样。修复前颜色最大变化67.67/255；最终普通路肩采样点均无变化，金属盖单个采样点最大变化2/255（0.78%）。全部原始值保存在shoulder-shadow-check.json，采用与远景检查一致的2%颜色差标准；最初1/255试探阈值的失败保留在日志，未称其通过。
- 同一个远端路段挂入检查，之前左路肩有4110个>2%变化像素；最终地平线与近场均为0。报告distance-transition-continuous.json。该固定视点验证不代表所有视点全帧绝对一致。
- 环境T1：Ruff、51项pytest、0/17/23三种子headless通过。新增检查只追加遮蔽坐标、原几何/法线/颜色/贴图保持，合批和重定位不改变遮蔽坐标。
- 最终弯坡1080p/12车/45秒有效前景窗口：实际绘制86.12FPS、P95 16.77ms、最长39.73ms，无>50ms帧、无采样丢时、无碰撞。前三秒预热另有0.333秒丢时，不计入正式采样。

独立包为builds/0.8.3-perf03/win_amd64；两个试玩启动器均已指向新包。仓库外启动、20次重开和44件高速资源哈希见PERF-03/package-check.json。用户实际画面确认待反馈；没有推送远端。
