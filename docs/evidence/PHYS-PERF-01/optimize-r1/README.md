# 持续低帧优化检查点

基线为 main `cf1316d`，本档案捕获其上的未提交优化。用户允许微小浮点差异；120Hz、硬件参数、方程和原收敛门槛保持。该功能块自动验证完成，整个性能任务继续，未发布产品包或推送。

## 实际结论

同一P核、GR86与8辆NPC、同输入128拍，旧／新／新／旧的32–96拍均值为100.420／59.309／59.613／99.685ms，平均下降40.57%。后续反力试探、四轮机械几何和已验证端口暖索引接入后，最终单次57.382ms；这是物理短测，不能称为FPS。单车14.611→6.802ms，弯坡九车77.964→50.419ms，参考车九车83.723→45.861ms均为独立单次对照。

四场景各128拍的完整快照中，位置、速度、姿态和事件均保持。单车及弯坡全字段相同；海岸九车仅6字段改变，最大2.36e-16；参考车1119字段改变，最大1.46e-11，见分类差异文件。独立旧DLL反力1024组、四轮机械几何2048轮逐值hex相同；边投影2048组正距离误差和非唯一内部见证点的边界仍见本地audit_edge记录。

1080p、GR86加8NPC、窗口保持前台的30秒实测仅1.768显示FPS，测量段丢时23.842秒。实际图像见window.png。该测量在后续反力/机械几何/端口小块之前，关闭声音，**性能失败**，不能据此宣称最终版已经流畅。九车仍远超8.33ms预算；下一步须拆开真实世界的读取/提交和纯数值车辆计算，保留唯一Bullet世界，以成熟引擎的并行数值序列方式推进。

## 验证与失败

较早完整车辆T1在600秒超时：1316/1743节点执行，1315通过、1个旧观测包装接口失败。仅修观测包装的第四参数后该节点通过；剩余427节点为426通过、1个落体制动旧对称假设失败。修正全部旋转轴的对称设置后，偏航/ESC/停车通过，但细化单调断言仍失败；独立旧源码得到相同停车距离58.996/58.829/59.080/59.380m。保留原断言和失败，不记完整车辆T1通过。

本批几何/缓存T1为605测试加0/17/23各1200拍通过；后续反力T1为452测试及三种子通过；最终机械几何/端口T1为514测试及三种子通过。各组重叠，不累计成唯一测试数。最终碰撞模块28通过、1个上述已复现旧失败节点明确排除。测试路径错误导致的两次pytest未执行和所有失败/超时仍在validation-summaries.json及本地原日志中。未运行T2/T3，人工驾驶待确认。

## 复现与来源

receipt.json列出范围、源SHA及档案SHA；timings.json保留每拍耗时。reproduction.zip含旧/新源码和独立DLL、完整海岸快照与测量脚本。解压后trajectory.py的ROOT需指向项目根，使用项目`.venv/Scripts/python.exe`；资源仍来自该项目，不依赖额外世界。固定P核仅影响测量进程，生产调度没有被修改。

依据来自[Panda3D PStats](https://docs.panda3d.org/1.10/python/optimization/using-pstats)、[PhysX车辆多线程示例](https://nvidia-omniverse.github.io/PhysX/physx/5.6.1/docs/Vehicles.html#snippetvehiclemultithreading)、[BeamNG虚拟机分工](https://documentation.beamng.com/modding/programming/virtualmachines/)、[Box2D暖启动](https://box2d.org/documentation/md_simulation.html)和[固定步追赶失控分析](https://gafferongames.com/post/fix_your_timestep/)。这些经验支持先定位CPU预算、复用实际静态几何和已验证分区、批量原生计算，继而让世界I/O串行而车辆数值并行。没有降低物理频率、删减车辆机制或关闭碰撞。
