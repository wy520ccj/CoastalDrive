# map160 耦合接触修正归档

## 结论

当轮胎几何迭代未收敛时，车辆仍执行原 `correct_contacts` 接触修正；最大20轮和全部既有阈值保持不变。生产改动仅在 `src/tire_drivetrain.py`，基线为 `e8e2a4f`。源码基线 SHA-256 为 `a270711048c57cd179a8caea7d31efcb5a698959ea0e85740feb7055e29270a7`，修复后为 `625d20d1bd033e5bc3ee3eceb4e463e7adb47ebab2a8bcc33f36227ce80ca2b7`；`src/tests/tools` 的354个 `.py/.c/.pyd` 起止哈希一致。

## 失败与复现

修复前整合 `PHYS-INTEGRATE-02-stage-T2-r4` 的 Ruff 通过，pytest 为18通过、point160失败，耗时701.03秒；其后11项未运行。失败发生于 map point 160 第97拍，轮胎力残差 `4.829883656e-5 N`、法向残差 `4.547474e-13 N`、几何残差 `6.904661e-12`。原单步输入重放复现该失败。以原 Newton 接触修正重放探针在10轮内收敛，能量残差 `-1.234689434e-14 J`。阶段原始摘要和日志完整保留，没有改写。

原 replay/probe 脚本曾带有从旧33657dc复制的 `kind` 元数据标签；标签已更正为 `e8e2a4f`，再运行原重放与探针。该元数据更正不改变此前 T2-r4 的原始失败记录。

## 修复后验证与边界

修复后 T0 为337项通过（5.23秒）及 Ruff 通过；T1 为785项通过（101.29秒）、Ruff通过，三个种子运行分别为10.825、10.952、11.004秒。健康单车/九车48拍完整快照与整合基线逐字段相同；`0.791594/6.213798`秒仅作诊断，不代表FPS或性能门槛。

由于接触求解源码已改变，旧 T2-r4 物理长轨迹不可直接复用，后续阶段复用需重新审查。主T2、T3、前台性能及人工驾驶Gate尚未完成；隔离 `e5765ed` 悬架性能块仍待整合，r6候选包来自旧源码。
