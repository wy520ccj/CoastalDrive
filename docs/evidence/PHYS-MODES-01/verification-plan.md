# PHYS-MODES-01 回归验证计划

本文定义两模式与参考车配置贯通后的短回归检查。执行顺序服从 PHYS-MODES-01：轮胎T2已完成；两模式接线先跑相关T0/T1，再按本计划收口新的T2。物理对照用独立新建的固定种子 Bullet world、同一平路/材料、同一初始状态与 1/120 s 步进。除特别说明外，车辆经静置 settle 后，以完整 `VehicleCommand` 输入，逐 tick 记录快照、车身速度/角速度、轮速及每轮接触法向载荷/滑移/轮胎力；有限值检查每 tick 执行。所有断言基于观察到的物理状态，不用模型公式在测试里重算被测结果。

## 接口与模式语义

| 检查 | 最小步骤与断言 | 目的 |
|---|---|---|
| 玩法模式与驾驶模式分离 | 遍历 `DrivingMode.GAME/SIMULATION` 与现有 `GameMode`；确认两者可独立选择，计时赛/自由驾驶/距离挑战仍按原玩法运行，驾驶模式选择不改变玩法规则。 | 防止把“仿真模式”误当一种比赛模式。 |
| 默认参数迁移等价 | 在重构前保存一个固定平路、无交通、固定 seed 的默认车 240 tick 轨迹签名（逐 tick 车身位置/速度/姿态、轮速、档位与转向）；重构后分别用默认构造和显式传 `VehicleConfig()` 重跑，同字段同 tick 对照。 | 检查隐式默认配置迁移没有改变现有 GAME 默认行为。比较容差取现有确定性基线的浮点读回误差，不扩大物理阈值。 |
| 相同配置/显式命令共用同一物理 | 分别以 GAME、SIMULATION 建两个零交通 test-track Simulation，配置对象值相同，给相同固定序列 `VehicleCommand`（方向、踏板、制动、齿条度数），逐 tick 对比玩家车与轮状态。 | 验证模式本身不分叉物理核心；命令绕过驾驶输入辅助。 |
| 游戏输入辅助 | 对真实 `DriverAssist.command` 输出检查踏板按配置渐进、速度转向包络收窄、低速刹车等待后才可辅助切倒挡；确认收到的 `Control` 仍是归一化量。 | 保留 GAME 输入手感和现有接口语义。 |
| 仿真输入语义 | 同一辆参考车以 SIMULATION 输入：踏板按输入直接到达执行器；`Q/E` 显式请求 R/D；齿条可请求完整机械限位角。没有显式方向请求时，不因长踩刹车自动换向。直接 `VehicleCommand` 不经过上述键盘逻辑。 | 键盘便利映射与机械执行器请求分开；不把满齿条角塞入归一化 Control。 |
| NPC 转向映射 | 对固定世界状态和同一目标角，检查 NPC 输入的目标角归一化使用其驾驶策略的 `steering_limit(speed, input_config)`；解码后得到原目标角（达到限位时明确饱和）。GAME 玩家键盘与 NPC 策略可不同，但 NPC 的生成/解码不可使用不同包络。仿真研究同轨迹时 NPC 与玩家都直接消费同一角度单位的命令序列。 | 防止只改车辆侧映射后，AI/NPC 仍按旧 CAR 全局比例错误转向。 |

## 配置生命周期与隔离

用两个互不相同的冻结配置 A/B 创建实例；至少在质量、轴距/轮距或轮位、轮胎摩擦/轮惯量中选取互异值。构造后让 A 车辆运行，再断言 B 对象及其 Bullet 读数不被污染。比较配置值和实际构造状态，不只比较 Python 引用。

| 生命周期 | 回归断言 |
|---|---|
| Vehicle 与子模型 | `Vehicle`、Powertrain、SteeringRack、DriverAssist、Tires 持有创建时所选实例配置；同一物理命令实际读取该实例值。动力辅助配置单独传递，不从另一个车型全局默认取得。 |
| reset / recovery | `Vehicle.reset`、玩家恢复/重置后配置身份和值不变；质量、轮半径、轮胎系数与轮位仍与创建该车时匹配，轮速初始化仍按项目规定的一次性初始条件处理。 |
| Session 重开/换赛道 | 同 mode 重开与同/异赛道重建后，Session 所选冻结配置不变；需要更换 DrivingMode 或车辆配置时重建 Simulation，禁止在已运行 Bullet 车上热换配置。 |
| NPC 建立与回收 | NPC 与玩家共享 Session 选定的 VehicleConfig；固定 seed 产生一次真实交通回收/stream recycle 后，回收前后的同一车仍使用原配置，Driver/Recovery 的控制策略状态按既有重置规则清理。无需长途循环；若既有短交通 fixture 可触发回收，直接用它。 |
| 模块实例互不污染 | 同进程同时持有 A/B Vehicle，交替推进后分别检查状态；禁止靠修改模块级 `CAR`、`WHEEL_HUBS` 来选择车型。 |

## 模式曲线、物理生效与观测

### 游戏补偿与通用参考车

- 固定配置表断言：GAME 选 C（原 B 非零节点 ×1.055），SIMULATION 的通用参考车选 B 原曲线；改变 Gameplay `GameMode` 不改变曲线选择。
- 通过真实 Powertrain/Bullet 短对照检查 GAME 的 160 km/h 游戏渐退和倒车力限额只在 GAME 启用。SIMULATION 同一 B 曲线在对应速度仍由转速、挡位、负载自然决定轮端力，不出现 `max_speed` 或 `reverse_force` 的游戏限幅；不能要求参考车达到某个任意“正确”极速。扭矩曲线高转端为零及传动关系造成的自然速度上限仍有效。
- 对照数据用同初始状态、方向与输入并标明 B/C、DrivingMode、输入策略、路面、固定步长；不根据单次加速时间宣称实车标定或物理验收。

### 参数确实进入力学链

机制实施可协同改变多个参数；下列参数敏感性试验用成对短 Bullet 试验隔离因果，每对改变对应配置量，材料/输入/初始状态/其他参数相同；记录实测响应方向与受力观测。阈值在基线测量后确定，只表达方向和高于读回噪声的差异，不用任意宽容差宣称精确度。

| 参数组 | 试验与必要证据 | 不能接受的“通过” |
|---|---|---|
| 质量 / 刚体惯量 | 质量 A/B 在相同低滑移牵引力命令下比较 Bullet 线加速度；较大质量的加速度响应较小。读取 Bullet 质量及 world inverse inertia；以同一外加小角冲量/力矩作短自由响应对照，惯量改变必须改变角速度响应。车身惯量若仍由碰撞盒推算，应记录配置几何和 Bullet 读数，不宣称有独立实车惯量标定。 | 只检查快照中的质量文本、静态轴荷估算或单轮惯量公式，不验证 Bullet 车身实际运动。 |
| 质心高度 / 前轴静态份额 | 在平地静置及受控纵向加速/制动时，比较每轮真实 contact normal load 总和。改变 `center_of_mass_height` 后，前后轴载荷转移的实测幅度随之变化；改变 `front_weight_share` 后，静态前后轴实际法向载荷按预期移动。观测必须来自 Bullet 接点/冲量或实际轮胎受力。 | 只见 `DynamicsState.front_load/rear_load` 诊断数字变化，而 Bullet wheel normal load、轮胎 Fx/Fy 不变。 |
| 轮胎摩擦 μ | 同速度制动与同转向输入分别做柏油高/低 μ 配对；低 μ 组记录到较低轮胎合力预算/纵向减速度，或者在相同要求力下有更大实测滑移。检查每轮接触状态与材料。 | 只对 `road_friction` 字段做对象值断言，或靠设置路面、速度瞬移改变结果。 |
| 轮转动惯量 | 相同驱动/制动力矩、相同轮载的起步/制动，比较实际轮速变化与车身纵向响应；增加 `wheel_inertia` 后轮角加速度应降低，转动动能/轮胎滑移时间过程随之变化。可用轮胎各轮冲量和 ω 观测核对角动量账。 | 只测试 Powertrain 发动机曲线或直接调用与实现相同公式重算 Δω。 |

选取现有快照/诊断中与参考车表 52 字段直接相关且有运行期意义的字段：位置、线/角速度、档位/RPM、中心与实际左右转角、四轮接触/法向载荷/法线、轮速、κ/α、Fx/Fy、制动与驱动转矩、气动/滚动/坡度力、源配置标识。验证 SIMULATION 快照每 tick 更新、有限且与状态对应；无接触时字段保持显式无接触语义，不伪造轮胎数据。配置表值应可从同一个被选配置序列化/报告，不能在测试里维护第二份参数常量表。

## 成绩与入口

- 用同一赛道/seed 分别以 GAME 与 SIMULATION 完成最短可保存成绩的赛段；两套成绩键空间各自写入和再读取，不覆盖另一模式。TIME_TRIAL/FREE_DRIVE/DISTANCE_CHALLENGE 的现有规则仍由 `GameMode` 决定，驾驶模式不改变计时/有效圈/挑战条件。
- UI 小检查只确认当前模式选项、选中态和驾驶中标签与 Session 实际 `DrivingMode` 一致；重开、返回菜单、换赛道后仍显示真实所选模式。主菜单/车库/外观变体不得静默切物理配置。
- headless CLI 使用同一 `DrivingMode` / VehicleConfig 入口，固定 seed、步数与模式记录在输出；无参数时仍走明确的 GAME 默认迁移路径。CLI 与 UI 不维护各自的曲线或参数映射。

## 执行顺序与收口

1. T0：配置值/曲线选择、控制单位及 DriverAssist/InputConfig 小检查；车辆构造读数；配置实例隔离；显式命令同物理短轨迹。
2. T1：`Session.start/reset`、跨赛道重建、玩家恢复、固定 seed NPC 创建/回收；模式成绩隔离；执行参数 A/B 物理方向检查。
3. T2：tools/validate.py T2的完整集合，加上本任务模式入口渲染检查。按仓库验证器运行一次，不重复当前仍在执行的 T2。
4. 记录真实命令、配置摘要/源码 SHA、seed、tick 数和逐组 A/B 观测；失败与未跑项分别标记。短自动测试、UI 实际渲染与人工手感结论分开记录。任何物理方向不符先保留输出并定位，不通过加宽阈值、仅改诊断字段或对运行车辆校准状态来掩盖。
