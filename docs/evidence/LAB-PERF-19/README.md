## 采用的改变

只改unsprung_joint.py，在每轮Jacobian构造前固定本Newton基点已算好的构型、完整速度项、速度+八接触力项。原最后一项缓存仍照常移动；回到基点且键的原始字节全部相同，才复用该点结果。构型在有限径向接触下仍按前十速度、旧冻结端口仍按完整十六速度；速度和接触力键不减少字段，区分正负零。

构型基点数据从本次velocity_data[0]取得，避免最后一项构型缓存与基点速度不一致；命中后同步原last key/data，保持下游force_key语义。每轮更新一个基点，全部缓存只属于本次solve闭包，不跨机械子步/世界/配置，不保存全部差分点。原数据只读复用，后续残差仍分配自己的输出。

原34列中央差分、epsilon、Newton/线搜索、精确端口行修正、30轮/12次上限、残差门槛和能量结果段从columns=[]起全文相同；构型/速度的数值计算段、反力和轮心力表达式AST保持，求值尾段保持。五个原生扩展及SDK完全不变，没有改变物理模型或参数。

## 为什么放弃道路候选C移植

先测未改道路查询，实体凸起诊断19.317s中，键0.288s、平面准备1.401s、实际实体生成器4.541s、候选选择/结果组装（扣除实体查询）1.239s、输出缓冲0.149s、已有原生帧0.151s。原完整输出一致，诊断含计时开销，不当作速度收益。

曾将候选控制流移入C，保留原查询、road_support回调、Python/NumPy比较分派、同距规则和异常顺序；三工况完整交叉结果一致，但收益不足：

| 未采用C候选 | 墙钟减少 | CPU减少 |
|---|---:|---:|
| braking | -1.92% | -2.30% |
| turning | 3.74% | 3.97% |
| nonlinear-bump | 0.77% | 0.17% |

C移植的Python对象与回调边界成本抵消了循环收益，制动反而慢约1.92%，凸起仅快0.77%；不采用，不把函数调用数下降当成整步提速。候选3份源码、wheel二进制、两个测试文件及完整结果都保存在candidate-selector与interleaved。撤回时核对生产源码和五扩展与7075998实验前逐字节相同，再实现基点复用；默认build/lib中的候选wheel也恢复为生产同SHA，避免后续构建拷回弃用版本。

C原型首轮23失败/36通过，原因是元组缓存键经C调用被拆成多个实参；修正原子传参后相关59项通过。最终候选26项与完整1728子步通过；测试闭包/Ruff格式问题已修正并保留日志。该候选没有跑完整691项，其结果不计作最终版本回归。当前生产不含C候选或新增C接口。
