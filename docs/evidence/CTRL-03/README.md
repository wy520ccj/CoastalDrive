# CTRL-03 横摆稳定控制

2026-10-01，本地源码开发。基线为 CTRL-02 `e1f1c0f`（物理实现 `6ac124c`）。全物理目标仍 active；本页记录自动机制验收，阶段人工驾驶、可见窗口性能及T3另验。

## 控制职责与模型

`vehicle_stability.py` 读取上一完整固定步的真实车身横摆率、速度、轮胎支撑和路面μ，输出分轮制动比例与可用驱动比例。驾驶者/TCS请求先合并，ESC再调节左右制动，真实25ms执行器和ABS实现最终压力；Powertrain沿用120ms转矩响应，两种削矩取较小可用比例。四轮自定义轮胎仍是唯一切向力来源；ESC不写车速、轮速、姿态或人工力矩。

右转齿条角为正，前进时车身横摆为负；倒车时横摆符号反转。参考 `r=-v*tan(δ)/L`，以实际支撑的总μFn/(m|v|)限制并进行150ms一阶响应。附着参考使用轮胎能力，不用制动硬件容量替代。侧偏参考由定常单轨关系得到：`tan(βref)=-lr*rref/|v| + m*front_share*v*rref/Cr`，其中 `lr=L*front_share`、`Cr=2*rear_lateral_stiffness` 为设计标称轴侧偏刚度。这是当前简化参考，真实轮荷、联合滑移与悬架仍由原力学核心决定。

`Mrequest=Iz*[6*excess(rref-r,0.10)-sign(v)*6*excess(β-βref,0.06)]`。归一化超阈值误差产生发动机削矩；不把正常低速转弯的非零β当成失稳。分配先释放反向制动，再增加同向制动；不足转向优先内后轮，其他纠偏优先前轮，受μFn与硬件容量约束。在四轮驾驶者请求均为1时，需要减小一侧请求才能纠偏；驾驶者踩刹车仍令动力总成驱动转矩归零。

`desired/baseline/allocated/residual` 是控制器的纵向制动力矩预测。逐帧文件另存真实累计轮胎冲量在采用的接点/姿态下还原的平均Fx/Fy横摆力矩；采用tick严格核对。该接点投影不包含轴反力、悬架、碰撞和其他外力，不称净车身横摆力矩。压力迟滞、ABS及联合滑移使实际接点力矩与理想分配不同。

设计依据：[Bosch ESP职责](https://www.bosch-mobility.com/en/solutions/driving-safety/electronic-stability-program/)说明转向意图、横摆观测、独立制动和发动机削矩的关系；[MathWorks制动试验](https://www.mathworks.com/help/vdynblks/ug/braking-test.html)提供低附着/对开附着车辆制动评价入口。当前增益、阈值、μ和标称刚度均为设计值；没有实车传感器或附着估计器证据。

## 同条件两模式A/B

正式文件为 [matrix-final/summary.json](matrix-final/summary.json)，两模式×9工况×2开关，36份全tick CSV gzip；每份721行，6s、120Hz。仅ESC开关改变，ABS/TCS保持开启；速度/纯滚动只在初始设置一次，滑行扰动仅初始赋予+0.5rad/s。独立水平Bullet平面、真实重力，无窗口。完成步横摆率直接读取刚体，施力前诊断另存，不混用时刻。全文字段并集保存离地/接触转换，源码运行前后哈希相同。
