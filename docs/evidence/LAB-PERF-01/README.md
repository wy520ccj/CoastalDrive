## 当前时间花在哪里

当前普通SDK另做24拍分项计时，总5.353s；与未插桩运行的全部25个完整快照逐字节摘要一致。

- 独立轮心共同求解48次，累计5.164s，约96.5%。每次均3轮收敛，即两次Newton更新后满足原收敛阈值，没有达到30轮上限。
- 每次更新对34个未知量双侧差分，构造Jacobian需68次完整残差计算。这个样本每个子步141次残差，24拍共6768次。
- 有限接触`evaluate`累计3.396s，约63.4%；内部真实径向几何查询4488次，累计0.972s。这里包含缓存命中；不能把6768次调用都说成6768次几何重建。
- 有限悬架运动累计0.162s，约3.0%。上述时间有嵌套，不能相加。
- Double另做6拍cProfile：`np.cross`调用47616次，连同通用轴检查/搬移约占采样时间57%；主要调用来自接触端口和几何组装。分析器放大小函数开销，该比例用于定位，未混入历史速度表。
- 同一采样中Bullet `doPhysics`十二次共约0.000614s；完整快照六次约0.000529s。该平路样本没有调用通用GJK的`signed_distance`。主要成本是Python/NumPy小向量与反复构造残差/几何，不能归咎于复杂碰撞或矩阵维度本身必然需要这么久。

源码入口：`src/vehicle.py:308`分流到`UnsprungAdvanceInput`；`src/vehicle_unsprung.py:155`直接调用Python `solve_unsprung_joint`；`src/unsprung_joint.py:193`构造双侧差分；`:106`在残差内刷新有限接触；`src/unsprung_contact_geometry.py:40`与`src/unsprung_drivetrain.py:88`反复构造几何和力端口。旧完整轮胎路径已有的原生`joint_solve`没有覆盖这套新增的独立轮心共同解。

这六个热点源码与合并前仿真分支`0944541`完全相同。本次合并的world_step改动位于单子步分支，本配置走两个子步。历史实测与代码共同表明主要慢点来自仿真分支已有机制；未把新合并或预载/非线性减振器功能笼统列为原因。

初始化也在真实执行相同物理：独立轮心各版本均195拍，成本随共同求解变贵一起从约7s升至24～28s；关闭独立轮心时实际177拍。不能把初始化耗时计成界面等待或将其省略后宣称启动性能改善。
