## 八项人工记录

使用 6B-04 的 `tools/impact_audio_check.py --drive --output <新目录>`，正常设备/正常音量，进入驾驶并聚焦游戏窗口。每项保留接近速度、物体、event_id、severity、layers、scrape 与主观结论。

| 场景 | 通过标准 | 用户结论 |
|---|---|---|
| 低速护栏轻碰 | 及时可辨，短而不刺耳 | 待试听 |
| 中速正面护栏 | 比轻碰明显，有车体反馈 | 待试听 |
| 高速重撞 | 重量/结构/少量碎片，发动机短暂让位 | 待试听 |
| 高速侧擦 | 初撞与连续摩擦自然衔接，不假装重撞串 | 待试听 |
| NPC 车辆 | 相对运动驱动强度，有车身质感 | 待试听 |
| 旋转后第二击 | 200–500 ms 后的新接触能再次清楚响起 | 待试听 |
| 连续擦碰 ≥5 s | 循环连续、退出利落、无机关枪声 | 待试听 |
| 翻滚/多次落地 | 当前物理能产生的实体接触有节奏且不过载 | 待试听/无法复现则说明 |

另做同类 ≥10 次重复检查，轻→重动态对比，静音/暂停/菜单/重开验证。明确区分轮胎悬架落地与底盘 manifold 撞地；不能为第8项修改物理或临时做假事件。自动夹具与用户能否在游戏中复现分别记账。

## 校准与验证

1. 从真实驾驶的静置/擦碰负样本核查物理噪声门槛，不让支持力/点替换进入 Impact。
2. 以轻/中/重代表区间冻结单调 log 曲线；核查 raw/excess 差异是否误吞第二击；高 vt、低 vn 应主要是 scrape。
3. 以相同日志/随机种子重放，对比 layer 电平、池内一致性、重触发与声音预算；离线输出峰值分析，真设备确认动态和音色。
4. 记录提交时间与回放提交延迟；若要端到端数字，用带游戏画面的系统音频录制测量，不能拿软件内部计时冒充扬声器延迟。

- T0/T1：用项目解释器执行 `tools/validate.py T0 --area audio` 与 `T1 --area audio`；若调整物理检测参数，加 core/gameplay。只对新改动补相关检查。
- T2：6B-04 有效结果可复用，除非接口/行为修改使之失效；T3 属整体6B/交付阶段，不自动启动。
- 通过条件：自动/后端证据完整且上述人工项获得真实结论。某项无法复现写明，不能勾选通过；本包完成不等于其他6B画面/性能缺口完成。
