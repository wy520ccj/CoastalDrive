# CTRL-02 驱动防滑TCS

- 状态：done；四轮真值滑转反馈、实际发动机削矩/分轮制动、严格关闭分支对照、T1与双分辨率渲染通过；完整物理阶段人工/性能待验。
- 基线：`bd0f9e4`，本地开发，未推送/发布。
- 用户目标：保持同一真实物理核心，用同工况无TCS A/有TCS B解释驱动防滑机制；电子系统独立于游戏/仿真输入策略。

## 范围与机制

TCS读取上一完成步的独立驱动轮速度与纵向滑转；通过发动机驱动请求削减、实际动力响应及必要的单轮制动抑制过度空转，不直接赋车速/轮速或放大轮胎附着。动力总成接收明确的可用驱动比例，制动执行器接收分轮请求；ABS处理制动滑移，两者职责清楚。先核对当前简化后驱等分转矩及发动机制动的适用边界，不把未实现的差速器或离合耦合称为已完成。

允许修改驱动防滑职责、Vehicle/Powertrain与Brakes直接接口、配置/状态/生命周期、电子配置菜单、标准加速工具和相关测试。其他玩法规则、碰撞、120Hz及唯一轮胎力保持。不引入控制管理器、第二套车身模型或反射式兼容。

## 验收

1. 固定相同车/初值/踏板，在高附着、低附着、split-μ、空中驱动轮与倒车起步中比较A/B。保存请求/可用驱动比例/实际转矩、分轮压力、ω/κ、Fn、Fx/Fy、车身速度/横摆/距离。
2. 验证驱动轮过度滑转、实际转矩削减及轮胎纵向力变化；不要求所有路面加速必然更快，不以显示TCS标志代替受力证据。
3. 松油门、刹车优先、低速/方向符号、腾空/recontact及reset/回收不继承旧介入状态。无TCS分支与CTRL-01冻结配置在同条件严格比较，不能暗改机械基线。
4. 与ABS共同工作时仍由同一单轮制动执行器产生转矩。真值速度辅助若沿用，明确标注；传感器/估计器另按功能实现。
5. 相关T0/T1和电子设置实际渲染；ABS/TCS/ESC功能组统一T2，完整阶段另做可见性能/人工驾驶。
