# 任务包与验证入口

仓库保存稳定事实，会话完成增量工作。新会话读根 `AGENTS.md`、`../current-progress.md` 和指定任务包；源码、测试及相关设计按需打开。历史 review 不作为启动阅读清单。

## 一条施工线

1. 规划：核对现状，复制 [TEMPLATE.md](TEMPLATE.md)，填目标、允许修改/禁止修改、可验收标准、基线 commit、T0/T1 命令。每包是一个完整功能块。
2. 实施：读任务包与相关代码 → 实现 → T0 → 修复 → T1 → 更新任务状态/当前进度 → 本地提交本任务成果。可拆分多个 commit；不要捎带其他工作。
3. 普通任务通过后直接接下一个已规划任务，不逐票重复高能力复核。核心接口变更、范围变化或两轮实质修复仍失败时，交出复现和具体决策点。
4. 小阶段收口：跑一次 T2，规划/复核模型只看 `git diff <base>..<head>`、进度和相关证据；有未提交修改时另看工作区差异，不把它们算入已提交范围。
5. 大阶段 Gate：任务包列出 T3 自动检查、实际渲染/性能、人工试玩三个部分，分别记结论。只有适用验收均完成才能宣布阶段完成。

状态使用 `ready / in_progress / blocked / done`；代码完成但人工体验待确认时写清自动部分完成、体验待确认。不要因自动脚本退出成功把人工项勾选为通过。

## 分级验证

在项目目录用 `.venv/Scripts/python.exe tools/validate.py ...`。`--dry-run` 只列出命令，不生成证据、不执行检查；`--output` 必须是新目录（相对路径以仓库为基准）。详细输出写入独立日志，终端只显示检查名/结果/耗时/失败日志路径。

| 级别 | 使用时机 | 当前实现 |
|---|---|---|
| T0 | 每次行为修改 | Ruff + 显式选定的模块测试或测试节点；未指定范围就报错 |
| T1 | 一个功能包完成 | Ruff + 相关模块完整测试 + 0/17/23 三种子各1200步 headless 启动；交通/道路额外0/23种子各30秒弯坡真实物理检查 |
| T2 | 一批任务或小阶段收口 | 完整 pytest、Ruff、headless 启动、车辆动力学、20组道路表面、交通交互、有限滨海/高速各30秒、0/17/23种子直路与弯坡各120秒 |
| T3 | 阶段自动 Gate | T2 + 0–9种子弯坡各600秒（12车）+ 无交通弯坡100公里；仍需该阶段专项、可见窗口/性能和人工结论 |

秒数指仿真时间；`--timeout` 是每条命令的墙钟上限，默认1800秒。T0/T1不会自动升级或重试。`workflow` 仅检查开发工具，T1不启动游戏；涉及游戏的任务不可用它替代相关模块验收。

模块：`core / vehicle / traffic / road / gameplay / appearance / workflow`，可重复 `--area` 合并。T0可以 `--tests tests/test_x.py::test_name` 只跑一个复现；T1应选完整相关模块。新增子系统同时补充 `tools/validate.py` 的模块映射。启动 smoke 只证明能够运行，不证明车辆行为/画面正确；新行为仍需针对测试。

```powershell
# 普通交通任务的两档检查
.\.venv\Scripts\python.exe tools/validate.py T0 --area traffic
.\.venv\Scripts\python.exe tools/validate.py T1 --area traffic
# 本次基底；不启动游戏
.\.venv\Scripts\python.exe tools/validate.py T1 --area workflow
# 小阶段；先预览再按需要实际执行
.\.venv\Scripts\python.exe tools/validate.py T2 --dry-run
.\.venv\Scripts\python.exe tools/validate.py T2
# 阶段长测预览；去掉 --dry-run 才实际运行
.\.venv\Scripts\python.exe tools/validate.py T3 --dry-run
```

`logs/validation/<时间>-<级别>/summary.json` 保存 Git HEAD、工作区状态、Python版本、选定范围、逐项命令/结果/耗时。测试用户设置隔离到该运行目录。日志已由仓库忽略规则排除；交接时将简短结果写入任务包，要跨机器交接则单独携带对应日志目录。未提交状态下的结果必须连同修改一起核对，不能只凭 HEAD 声称该 commit 已通过。

失败时停止，未执行项保留 `not_run`；非零退出、超时、中断、缺失/损坏结果文件、`passed` 非 true 都不能通过。部分旧脚本即使报告失败也退出0，入口额外检查其JSON结论。历史脚本不是批量通配执行：过期接口及固定输出位置的脚本仅在相关任务核对后使用。T2列表就是当前自动回归集合，新增回归须显式加入。

## 实际渲染、体验与阶段复核

UI/素材/声音任务的T1还需任务包指定的离屏或可见验证，检查实际渲染结果；通用入口保持无窗口，不自动抢占桌面。声音需正常设备试听。T3中的12车长测不能证明18车繁忙交通；繁忙交通、复杂事故、严格可见30分钟、内存平台、1080p帧耗时等仍按开发计划专项验收。

每个阶段任务包保留以下记录，未执行填“待执行”：

| 验收项 | 版本/场景/种子 | 命令或操作 | 证据路径 | 结论与未完成项 |
|---|---|---|---|---|
| T2 / T3 自动 | | | | |
| 可见窗口/性能/内存 | | | | |
| 人工驾驶/画面/声音 | | | | |

高能力复核入口可直接使用：

> 读 AGENTS.md、docs/current-progress.md 和任务包 <ID>。复核 <base>..<head>；核对 T2 证据与未提交差异，重点看本批架构偏移、行为退化和测试是否覆盖真实风险。只按需打开相关设计，不重审无关历史。人工 Gate 未完成时保留待确认。

新实施会话可直接使用：

> 读 AGENTS.md、docs/current-progress.md 和 docs/tasks/<ID>.md。按包完成实现、T0/T1、结果记录及本地提交；不要扩大范围，卡住时留下复现、失败日志和下一决策点。
