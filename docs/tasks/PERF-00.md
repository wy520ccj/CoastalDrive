# PERF-00 — 启动与运行期性能基线

基线：`8fa19e1`，分支 `visual-identity-v1`。状态：仪表、源码/独立版启动及 1080p 八车运行期基线均已完成。本包只建立测量，不做性能优化或加载架构。

## 范围

允许修改 `src/main.py`、`src/application.py`、`src/scene.py`、`src/vehicle_visual.py` 的显式计时点，以及独立的 `src/performance_baseline.py`、`tools/performance/profile_startup.py`、已有运行期测量脚本、定向测试和本任务文档/证据。禁止改 Simulation、车辆物理、交通规则、游戏流程、UI/3D资产、shader实现、资源加载方式或引入异步/管理器/线程池。

启动测量是每次全新 Python 进程、1280×720 可见窗口：进程创建前 → 入口/导入 → Panda/窗口 → simplepbr 初始化 → 世界/环境 → 主车 GLB/反射资源 → 零辆交通车的菜单 → 字体/UI → 首个渲染帧与可见可选菜单。随后单独计时进入滨海自由驾驶、加载八车及首个驾驶帧。屏幕截图验证菜单像素已渲染；`taskMgr.step()` 返回是应用侧首帧完成点，并非操作系统显示扫描时间。间隔包含相邻测点之间的其他工作，不能解释为单函数独占 CPU 时间。GPU shader 编译未单独计时，可能落在首帧区间。

每次进程启动不清系统文件缓存或驱动 shader 缓存，因此本报告称“新进程启动”，不是重启系统后的严格冷启动。三次中位数便于长期比较；运行期继续沿用 1920×1080、八车、种子 23、30 秒预热 + 300 秒正式采样。运行图几何量改在八车场景创建后、采样结束时统计；ENV-02/VEH-01 原报告是在首帧前统计，旧几何量不可直接横比。

## 验收与复测

- `tools/performance/profile_startup.py --output <全新目录> --runs 3`：每次有时间线 JSON、菜单首帧 PNG；主菜单可见，进入驾驶后恰有 8 辆车。
- `tools/environment/drive_slice.py --onscreen --benchmark --output <全新目录>`：保存平均 FPS、P95/P99、正式采样丢弃仿真时间、节点/Geom/三角形数量；不以本包改变 60 FPS/P95 25 ms 门槛。
- `tools/validate.py T0 --tests tests/test_performance_baseline.py`；`T1` 加入与启动接线相关的 UI/车辆资产测试及三种子 headless。
- 结果记录于 `docs/evidence/PERF-00/`。已有 ENV-02/VEH-01 运行期数值直接引用原 JSON，启动时间均为未知，不补推断。

本包不做性能根因判断或优化。下一阶段可依据测点选择窄范围诊断。

## 本轮执行结果

- 启动三次：菜单首帧/可用 7.5657、7.1964、7.3722 s，中位数 7.3722 s；菜单后进入滨海八车自由驾驶额外中位数 2.3664 s。菜单首帧截图已检查为完整画面。
- 从本轮构建的 `builds/0.8.3-perf00/win_amd64/coastaldrive.exe` 独立版再测三次：菜单首帧/可用中位数 7.2819 s，八车切换额外中位数 2.3371 s；实测首帧截图与源码版一致。打包时仍有系统 DLL 查找警告，本机启动成功，未做干净机器验收。
- 运行期：1080p、八车、种子 23、30 s 预热 + 300 s 正式采样。平均 47.62 FPS、P95 26.28 ms、P99 30.20 ms；正式采样丢弃 0.0167 s。节点 730、GeomNode 359、Geom 1546、三角形 312642，场景图在八车加载后统计。现有 60 FPS / P95≤25 ms 门槛未通过；仅凭本次与历史差异不能判定根因。
- 首次长测向控制台持续输出大量补帧警告，已主动中断，无完整报告，不用于性能比较。第二次将控制台输出定向到文件后完成完整采样，日志仅有预热期一次补帧警告；保留其原始 JSON 和运行日志。
- T0：Ruff、2 项定向测试通过。T1：Ruff、34 项 UI/车辆资产/环境/时间线相关测试及 0/17/23 三种子 headless 通过；完整摘要在 `logs/PERF-00/T0` 与 `logs/PERF-00/T1`。
