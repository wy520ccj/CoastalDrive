# PHYS-TIRE-04 再接触闭环精度与求解效率

- 状态：ready；在PHYS-TIRE-03轮胎功能组T2及授权提交/推送后开始。
- 基线：PHYS-TIRE-03提交的reference-v6与对应源SHA，开始时记录实际Git HEAD；不使用历史单轮原型代替当前生产模型。
- 目标：处理柔性轮胎再接触时的数值精度与电子反馈分支，降低四轮共末速度求解的实际计算成本。同一机制与默认120Hz物理核心，不建立第二套世界或通用求解框架。

## 已有证据

[再接触隔离](../evidence/PHYS-TIRE-03/recontact-sensitivity/findings.md)：困难仿真、100km/h离地制动，ABS on的2/4子步累计航向约+0.4°，8/16约−4.6°；8→16仅差0.028°，4→8发生分支变化。ABS off2/8航向差降至0.412°，但两条本身偏航更大；TCS/ESC仍on，不能唯一归因ABS。最早调压差tick77，完成横摆差tick80，左右轮荷差tick97。能量与力残差合格不能证明默认2子步响应精度收敛。

PHYS-TIRE-03的12车30s弯坡自动检查墙钟约164s。它是整脚本时间，不能当画面FPS，但提示新求解路径需要计算成本验证。公开独立包仍为RADIO-02，物理源码入口是`试玩-物理开发.cmd`。

[调用次数基线](../evidence/PHYS-TIRE-03/solver-call-profile/summary.json)在三条独立水平面工况各120tick、默认2子步下统计：加速/恒定3°转向/制动，每车每子步局部轮胎求解平均15.58/15.50/12.00次，残差求值433.20/340.43/313.05次。每次局部求解从零力初值开始；该重复迭代是下一步可查的具体位置。剖析改变执行耗时，因此此处只用调用计数，不推断帧率或稳态驾驶响应。

## 范围与顺序

1. 从现有全tick轨迹定位接触、制动/稳定反馈与子步末速度的最早因果分叉。补必要的隔离或更小步长试验，保留完整输入、配置和原始数据，不重跑无关长实验。
2. 主线复核时间离散与闭环事件；确定有物理依据的修正再实施。不能仅把默认步数提高至8就宣称问题和性能都已解决，也不靠调整发动机、轮胎峰值或电子增益掩盖积分误差。
3. 同一耦合方程的重复计算、局部/全局迭代收敛路径是本功能允许范围；明确接口、直接数据。任何求解改动必须验证稳态、作用/反作用、制动互补、低速静摩擦、离地松弛和总能量，不加失败时的另一套力模型。
4. 若电子阈值附近的分支属于实际闭环敏感性，给出原始证据、来源及精度协议；不能用“所有求解都收敛”替代输出响应的数值验证。

## 验收

- 刚性关闭分支保持冻结既有值；两模式共用机制，玩家/NPC与reset/rebase/回收状态保持一致。
- 保留0.001N接触力残差与预算容差、原制动功/总能量/坡停/交通碰撞门槛。路面功保留符号，误差界按对应力残差和真实时间步推导，不钳负值。
- 同配置/输入的2/4/8/16子步再接触，以及常规转向/制动/倒车等A/B，保存全过程。参数若因完整机制而协同变化，明确列出，不归为“仅数值变化”。
- 相关T0、完整vehicle/core/gameplay/traffic/road T1、功能组T2；旧失败与not_run保留。
- 求解效率以相同物理工况/脚本比较，实际窗口帧耗时另测并记录前台状态；完整T3和人工驾驶继续属于总阶段Gate。
