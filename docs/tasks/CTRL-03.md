# CTRL-03 横摆稳定ESC

- 状态：ready；依赖CTRL-02收口，ABS/TCS/ESC功能组统一T2。
- 目标：正常游戏与困难仿真共享物理控制机制，在split-μ制动、转向阶跃和弯中制动中检验单轮制动产生的真实横摆力矩。
- 旧证据：CTRL-01开启ABS的split-μ制动仍累计转向约190°，不能用TCS起步直线结果替代制动稳定性。

## 范围与机制

独立横摆控制职责读取上一完整步的实际车速、齿条角、横摆率及侧偏，生成明确的发动机可用驱动比例与分轮制动请求。参考横摆由转向几何和车辆参数产生，依据轮胎附着的能力限制可达目标；先确认转向、航向、横摆及接点制动力矩的左右符号。首版反馈取仿真真值，速度估计器与真实传感器另立任务。

制动请求由现有四轮有限响应执行器实现，ABS继续负责车轮制动滑移；发动机请求与TCS统一进入Powertrain现有转矩响应。驾驶者、TCS与ESC的请求仲裁按实际职责直接写清楚，不引入Manager、电子控制框架或第二套车辆状态。ESC不能直接写车速、轮速、姿态、横摆率，也不能增加人工稳定力/力矩或提高μ。

允许改横摆控制职责、车辆/动力/制动直接接口、电子参数与快照、reset/回收/插值、现有菜单与CLI、标准试验及相关测试。保留120Hz、独立四轮转动、唯一轮胎力和真实碰撞。差速器、悬架硬件与估计器不在本任务展开。

## 验收

1. 同车、同初值、同控制时序保存无ESC A/有ESC B的逐tick轨迹；至少包含铺装、低附着、split-μ直线制动、弯中制动与转向阶跃。记录请求/实际分轮压力、Fx/Fy、轮荷、κ/α、发动机实际转矩、期望/实际横摆、侧偏和解卷绕航向。
2. 验证选中车轮的真实接点力产生正确方向的横摆力矩，介入后误差与失稳程度的变化符合机制。不预先要求所有工况停车更短或横摆恒为零；目标不可达时明确记录饱和及剩余误差。
3. ESC关闭分支与CTRL-02冻结机械状态严格对照；电子开关与输入策略独立，松踏板、低速、倒车、离地/再接触与驾驶者制动优先分别验证。
4. reset、NPC回收、模式重建清除状态；坐标重定位保留连续物理记忆，显示插值使用最近真实控制反馈；玩家与NPC共用配置/实现。
5. 相关T0/T1、两分辨率电子页面/HUD实际渲染通过后，统一执行ABS/TCS/ESC功能组T2。完整物理阶段的T3、可见窗口性能与用户驾驶体验分别记录。

## 后续入口

电子控制收口后审阅轮胎瞬态与轮荷敏感性、传动耦合/驱动布局、悬架与惯量标定，以及真值反馈到速度估计的职责。按对通用参考车真实性的实际影响排序，再接真实车型。
