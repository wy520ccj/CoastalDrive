# 车库页面：从叠加控件改为组织关系

用户指出上一版像强行堆叠、互相覆盖。检查实际图，问题成立：车辆展示跨越了底部选择带，右侧信息卡遮住车头；所有入口都用大圆角块，主次不清；改装操作与对应部件分散。这些版本不作为视觉完成依据。

## 阅读与采用

| 阅读来源 | 学到的原则 | 本项目直接改动 |
|---|---|---|
| [NN/G Proximity](https://www.nngroup.com/articles/gestalt-proximity/) | 用距离表达关系；相关内容靠近，不相关分组留出更大间隔 | 车辆选择带只位于车模下方；价格/状态/安装集中到对应零件；返回固定页尾 |
| [NN/G Visual Hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) | 通过大小、对比和分组给出阅读顺序，不让所有控件同等抢眼 | 车辆是展示主体；车型名次之；指标降为辅助；标签页使用文字与下划线，只有当前主要动作使用实色 |
| [Xbox XAG112](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112) | 页面结构、操作位置与焦点顺序要稳定，按视觉含义组织导航 | 固定返回/标签/主体/页尾区域；键盘默认焦点放主要动作，禁用项不执行；选车预览与确认分开 |
| [FH5 Upgrade Heroes](https://forza.net/news/forza-horizon-5-upgrade-heroes) | 在车辆上理解改装，试驾后决定保存/放弃 | 我的车辆、升级和涂装集中车库；鼠标聚焦零件关联车模部位；未确认的车辆/颜色不写当前车 |

只学习机制、空间关系和操作顺序，不复制对方美术。搜索到的第三方攻略截图仅作线索；远程截图读取失败，不能声称已直接看过所有原图。

## 新布局约束

- 一条固定网格：上方上下文与文字标签；左侧完整车辆展示；右侧当前功能；左下与车辆相关的选择/说明；页尾返回与状态。
- 车辆区、右侧操作区、选择带、页尾互不覆盖。镜头根据实际车模外廓与视口比例构图，车轮、车顶均留边。
- 选车页：左侧看车，左下换车，右侧确认驾驶。升级页：车辆区保持，右侧只放零件/作用/安装；涂装页：右侧选择颜色并应用。
- 统一三档文字、间距和动作颜色；移除纯装饰性浮动信息卡，避免靠层层白色容器制造分组。
- 两种画幅分别渲染；实际投影外廓确认车辆完整落在预留区域。自动检查只能证明布局和流程，不代替用户的视觉与手感评价。
